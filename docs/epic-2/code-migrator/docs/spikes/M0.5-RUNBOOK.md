# M0.5 harness spike — operator runbook

> **Current path (native, `D-NATIVE`).** opencode was abandoned. The live run now
> uses render-agents' **native engine** + the `workspace` tools. To run it:
> from the render-agents repo root, ensure an LLM key is available
> (`ANTHROPIC_API_KEY` in `examples/demo/.env`), then:
> `PORT=3020 examples/demo/scripts/spike-run.sh --skip-build`
> It boots the gateway (memory store), dispatches `leven-migrate` (clones leven →
> `migrator` agent ports JS→TS → parity oracle), and prints the run + parity
> result. **Pass = workflow `status: completed` and `parity.ok: true`** (gates:
> `index.ts` exists, deps, `npx tsc --noEmit` exit 0, `npx ava` green). Only a
> provider key + Node/git are required — no opencode binary.

## Prerequisites

| Requirement | Notes |
|-------------|--------|
| **Node ≥ 20, pnpm** | From repo root: `pnpm install && pnpm build` |
| **LLM provider key** | `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` (env or `render-agents/examples/demo/.env`) |
| **opencode runtime** | Global `opencode` on PATH **or** `npx opencode` resolving; SDK `@opencode-ai/sdk@1.18.3` boots via `createOpencode()` unless `OPENCODE_BASE_URL` points at an existing server |
| **git** | Shallow clone of [sindresorhus/leven](https://github.com/sindresorhus/leven) |
| **curl** | Dispatch + health checks |

Optional (not used by the default spike script):

- **Docker + Postgres** — hybrid local-dev flow in `examples/demo/README.md` (`DATABASE_URL`, Render CLI). The spike script uses the **in-memory store** (no `DATABASE_URL`) for simplicity.
- **`OPENCODE_BASE_URL`** — connect to a pre-running `opencode serve` instead of per-run boot.

## Quick run (recommended)

From **render-agents** repo root (on `spike/m0.5-opencode-runtime`):

```sh
chmod +x examples/demo/scripts/spike-run.sh   # once
examples/demo/scripts/spike-run.sh
```

Usage / env overrides:

```sh
examples/demo/scripts/spike-run.sh --help

PORT=3000 LEVEN_DIR=/tmp/leven ./examples/demo/scripts/spike-run.sh
./examples/demo/scripts/spike-run.sh --skip-build    # already built
./examples/demo/scripts/spike-run.sh --no-start      # gateway already on PORT
```

Defaults: `PORT=3015`, `LEVEN_DIR=$TMPDIR/m0.5-leven`, `RENDER_AGENTS_API_KEY=dev-key`.

The script prints **run id**, **operator UI URL** (`/ui`), and how to stop the gateway.

## Manual run

### 1. Clone leven

```sh
export LEVEN_DIR="${TMPDIR:-/tmp}/m0.5-leven"
git clone --depth 1 https://github.com/sindresorhus/leven "$LEVEN_DIR"
```

### 2. Build + export env

```sh
cd render-agents
pnpm install && pnpm build

export PORT=3015
export RENDER_AGENTS_API_KEY=dev-key
# export ANTHROPIC_API_KEY=...   # or OPENAI_API_KEY, or use examples/demo/.env

unset DATABASE_URL
unset RENDER_USE_LOCAL_DEV
```

### 3. Start gateway (memory store, inline)

```sh
cd examples/demo
set -a; [ -f .env ] && . ./.env; set +a
pnpm exec tsx src/server.ts
# → gateway listening on :3015 (executionMode=inline)
```

Confirm: `curl -s localhost:3015/health` → `{"status":"ok"}`.

Open operator UI: `http://localhost:3015/ui` (API key `dev-key` when prompted).

### 4. Dispatch leven-migrate

```sh
curl -X POST "localhost:3015/workflows/leven-migrate" \
  -H "Authorization: Bearer dev-key" \
  -H "Content-Type: application/json" \
  -d "{\"input\":{\"repoPath\":\"$LEVEN_DIR\"}}"
```

Response `202` with `{ "id": "<run-uuid>", ... }`. Poll:

```sh
curl -s "localhost:3015/runs/<run-uuid>" -H "Authorization: Bearer dev-key"
```

### 5. Stop

`Ctrl+C` the gateway terminal, or `kill <pid>` if backgrounded.

## What PASS looks like (H1–H5)

### H1 — Headless drive

**Pass:** Child agent run starts; terminal/log shows opencode boot (or connect to `OPENCODE_BASE_URL`). In `/ui` for the **leven-implementer** child run:

1. `run.started`
2. `message.user` with the migration prompt
3. Assistant/tool activity through the turn
4. `run.completed` (or `run.failed` with a clear error — not a hang)

SDK path: session create → prompt with `body.agent` set to the agent name (see H2 / #6573).

### H2 — Custom subagent / role selection

**Pass:** Prompt targets **`leven-implementer`** via `body.agent` (defined in `opencode.json`), not nested Task-tool `subagent_type` spawning. Model is declared in config (env placeholder). No hang at session prompt.

Unit tests already cover mapper/runner shape; live pass = prompt completes under the named agent.

### H3 — Self-correction on leven

**Pass:** During JS→TS port of `index.js`:

1. Type/LSP diagnostics appear (`tool.called` / `tool.result` for `lsp.diagnostics`, or equivalent tool messages).
2. Agent edits again without human input.
3. Workflow **parity** step succeeds: `tsc` clean and **`ava` tests pass** in the cloned leven repo (same behavior as upstream).

Terminal: workflow status `completed`; run output/summary mentions successful parity.

### H4 — Observability bridge

**Pass:** In `/ui` trace for the implementer run, granular events including:

- `tool.called` / `tool.result` for **file edits** (`file.edit`)
- LSP diagnostic events when types break
- `message.assistant` chunks
- Parent workflow run shows child delegation/spans linking to the agent run

Event log API: `GET /runs/:id/events` (Bearer token).

### H5 — Durability / idempotent re-trigger

**Pass (full):** Under **Render Workflows local dev** (`render workflows dev` + Postgres — see `examples/demo/README.md` hybrid section), dispatch the same workflow twice with the **same idempotency key** for an `agent.task()` child; second trigger returns memoized output, **no duplicate run**.

**Spike script default (memory + inline):** H5 is **not** fully exercised — durability memoization is validated in unit tests; note result as “deferred to hybrid/Postgres run” if only the script was used.

## Reading the operator UI (`/ui`)

1. Open `/ui`, authenticate with `RENDER_AGENTS_API_KEY` (`dev-key` by default).
2. **Runs list** — find the workflow run (`leven-migrate`); status progresses `running` → `completed` or `failed`.
3. **Run detail** — timeline of lifecycle, messages, tools, steps:
   - **Lifecycle:** `run.started`, `run.completed` / `run.failed`
   - **Steps:** workflow `ctx.step("parity", …)` as `step.started` / `step.completed`
   - **Tools:** expand `tool.called` → `tool.result` pairs (edits, LSP)
   - **Children:** navigate to nested **leven-implementer** agent run for opencode-granular events
4. **Live updates:** SSE stream on `/runs/:id/stream` (UI uses this internally).

Correlate with raw events:

```sh
curl -s "localhost:3015/runs/<id>/events" -H "Authorization: Bearer dev-key" | jq .
```

## Troubleshooting

### opencode / prompt hangs

- **Known issue [#6573](https://github.com/sst/opencode/issues/6573):** driving **nested Task-tool subagents** via `opencode serve` can hang.
- **Mitigation in this spike:** select the role with **`body.agent`** on `session.prompt` (primary path in `runners/opencode.ts`); do **not** rely on `subagent_type` nesting for the implementer.
- **Timeout:** runner enforces wall-clock timeout; hung prompts should end in `run.failed` with timeout message.
- **Workaround:** set `OPENCODE_BASE_URL` to a separately managed `opencode serve` instance.

### Missing LLM key

Gateway health works without a key; agent turns fail at model call. Export `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`.

### opencode binary not found

`createOpencode()` needs the CLI/runtime. Install globally or verify `npx opencode --version`. Check gateway log under `$LEVEN_DIR/.spike-logs/gateway.log` when using `spike-run.sh`.

### Port already in use

Set `PORT=` to a free port (default `3015` avoids Docker demo on `3000`).

### Empty UI / runs disappear after restart

**Memory store** (no `DATABASE_URL`) is ephemeral — restarting the gateway clears runs. For persistent traces, use Postgres (`DATABASE_URL` + `docker compose up -d postgres`) as in `examples/demo/README.md`.

### Parity step fails

- Inspect leven checkout: was `index.ts` created? Run manually in `$LEVEN_DIR`: `npm install && npm test`.
- Check implementer run for uncorrected LSP/type errors before parity.

### Workflow 404

Confirm branch has `examples/demo/workflows/leven-migrate/index.ts` and gateway was started **after** build so `loadProject` registers the workflow.
