# M0.5 — Implementation plan (decomposition + interfaces)

Companion to `M0.5-harness-spike.md`. This is the buildable decomposition handed to implementation subagents, plus the exact seams pinned from the codebase.

## Where the work lives

- **Branch:** `spike/m0.5-opencode-runtime` (in the `render-agents` repo — `D-BASE`).
- **Harness:** `examples/demo` (already wired: `loadProject(root)` auto-loads `runners/*.ts`, `agents/*.md`, `workflows/<name>/index.ts`). Additive files only; **do not edit core packages**.
- `@opencode-ai/sdk@1.18.3` is already installed in `examples/demo`.

## Scope boundary (environment reality)

No LLM API keys and no running Docker daemon are available in the build environment. Therefore:

- **Build + typecheck + mocked unit tests** are the acceptance bar (memory store, a `FakeOpencodeDriver`). Fully achievable.
- The **live run** (real opencode + real model porting `leven`, Postgres-backed UI) is delivered as a **gated script + runbook** for the operator to run with credentials — not executed here.
- Hypotheses validated here: **H1** (drive shape), **H3/H4 logic** (self-correction loop + event mapping, via fakes). Hypotheses gated to live run: **H3/H4 end-to-end, H5 durability**.

## Pinned seams

### render-agents `AgentRunner` (the extension point)

```ts
// packages/engine/src/context.ts
interface AgentRunner { run(agent: AgentDefinition, input: AgentInput, ctx: RunContext): Promise<AgentOutput>; }
// AgentOutput = { text: string; data?: unknown; usage: { inputTokens: number; outputTokens: number } }
```

- `RunContext` (packages/engine/src/context.ts) provides: `emit(event: RunEvent)`, `streamDelta(text)`, `messages(agentName)`, `isCancelled()`, `hasStarted()`, `signal: AbortSignal`, `runId`, `mountTools(ids)`.
- Runner registration: default-export an `AgentRunner` from `examples/demo/runners/opencode.ts`; reference via agent frontmatter `runner: opencode`. Validated at load time (`validateRunner`).
- Observability = emit from the **closed** `RunEvent` union (packages/store/src/events.ts): lifecycle `run.started|run.completed|run.failed`; `message.assistant|message.tool`; `tool.called|tool.result`; `llm.call`; `step.started|step.completed`. No custom event types — map opencode events onto these.

### opencode SDK v1.18.3 (pinned)

- `createOpencode(opts?)` → `{ client, server:{url,close()} }` (boots server + client); `createOpencodeServer(opts?)` → `{url,close()}`; `createOpencodeClient({ baseUrl, throwOnError? })` → client (connect to running server).
- `client.session.create({ body:{ title? }, query:{ directory } })` → `.data` is `Session` (`.id`).
- `client.session.prompt({ path:{ id }, body:{ parts:[{type:"text",text}], agent?, model?:{providerID,modelID} }, query:{ directory } })` → `.data` = `{ info: AssistantMessage, parts: Part[] }` (blocks until the assistant turn completes).
- `client.event.subscribe()` → `{ stream }` async-iterable of `Event`. Relevant members: `EventFileEdited`, `EventLspClientDiagnostics`, `EventMessagePartUpdated` (carries `ToolPart`/text), `EventSessionIdle`, `EventSessionError`.
- **#6573 caveat:** driving the *Task tool's nested subagents* via `opencode serve` can hang. Select the role via **`body.agent`** on the prompt (primary path); do **not** rely on nested `subagent_type` spawning for the spike. Add a wall-clock timeout guard.
- Read the real types before coding: `node_modules/.pnpm/@opencode-ai+sdk@1.18.3/node_modules/@opencode-ai/sdk/dist/{index,server,client,gen/types.gen}.d.ts`.

## Decomposition

### Round 1 — Foundation (one subagent)

Files under `examples/demo/`:

1. `lib/opencode/driver.ts` — narrow, mockable interface + real impl:
   ```ts
   interface OpencodeDriver {
     start(dir: string): Promise<void>;                 // createOpencode, or connect if OPENCODE_BASE_URL set
     createSession(dir: string): Promise<{ id: string }>;
     prompt(a: { sessionId: string; dir: string; text: string; agent?: string;
                 model?: { providerID: string; modelID: string } }): Promise<{ text: string; usage: { inputTokens: number; outputTokens: number } }>;
     events(signal: AbortSignal): AsyncIterable<OpencodeEvent>;  // wraps event.subscribe()
     abort(sessionId: string): Promise<void>;
     stop(): Promise<void>;
   }
   ```
   Real `SdkOpencodeDriver` uses the pinned SDK. Env: `OPENCODE_BASE_URL` (connect) else boot via `createOpencode`.
2. `lib/opencode/events.ts` — pure `mapOpencodeEvent(ev): RunEvent[]` (file edit → `tool.called`+`tool.result`; LSP diagnostics → `message.tool`/`tool.result`; tool part → `tool.*`; assistant text → `message.assistant` (+ `streamDelta` handled in runner); session error → `run.failed`).
3. `runners/opencode.ts` — `AgentRunner`: connect/boot driver at the target dir; subscribe to events concurrently; send prompt with `agent = definition.name`; pump `mapOpencodeEvent(...)` through `ctx.emit`; honor `ctx.signal` (→ `abort`) and `ctx.hasStarted()`; enforce a timeout; return `AgentOutput`. Emit `run.started`/`run.completed`/`run.failed` around the turn.
4. `tests/opencode-events.test.ts`, `tests/opencode-runner.test.ts` — vitest with a `FakeOpencodeDriver`: mapper table tests; runner emits correct event sequence; simulated diagnostics→fix self-correction; cancellation aborts. No network/keys.
5. Add `"test": "vitest run"` + `"typecheck": "tsc --noEmit"` to `examples/demo/package.json`.

**Acceptance:** `pnpm --filter @render-agents/example-demo typecheck` and `... test` green.

## Review gates (parent)

After each round: read every new file, run typecheck + tests, and check for **bugs, logic gaps, code smells** — specifically: concurrent event-stream vs prompt race + idle/termination detection; cancellation/timeout cleanup (no leaked server/subscription); `.data`/error handling on SDK calls; event-mapping correctness + span correlation; resume safety (`hasStarted`); adherence to ESM/strict-TS/repo conventions; no edits to core packages.
